# Данные для обучения модели

Папка для записей, разметки и датасета. В git попадает только код и этот README,
сами видео и датасет — нет (см. `.gitignore`).

## Структура

```
train_data/
├── README.md              этот файл
├── labels.csv             разметка эксперта (вы заполняете)
├── labels.example.csv     шаблон разметки с примерами
├── videos/                записи попыток: s01_01.webm, s01_02.webm, …
├── dataset.csv            получится после export_dataset.py (не в git)
├── skeletons/             скелет 33 точки по попыткам (не в git)
└── report.md              отчёт обучения (не в git)
```

## Как назвать файлы

`<студент>_<номер>.webm` — например `s01_01.webm`, `s01_02.webm`, `s02_01.webm`.

Важно: **номер студента должен совпадать в имени файла и в разметке**. По нему
скрипт делит выборку так, чтобы кадры одного человека не попадали одновременно
в обучение и проверку. Если это правило нарушить, точность покажет 95%, а в жизни
модель не будет работать.

## Формат labels.csv

| Столбец | Что писать |
|---|---|
| `id` | уникальный номер попытки, лучше как имя файла без расширения: `s01_01` |
| `file` | имя файла в `videos/` |
| `student` | код студента: `s01`, `s02` — один и тот же для всех его попыток |
| `expert` | кто размечал: `expert_A`, `expert_B` |
| `date` | дата записи, `2026-11-05` |
| `tempo_ok` | темп 100–120 в минуту: `1` да, `0` нет |
| `depth_ok` | глубина 5–6 см: `1` / `0` |
| `arms_straight_ok` | локти не согнуты: `1` / `0` |
| `arms_vertical_ok` | руки вертикальны: `1` / `0` |
| `hands_together_ok` | кисти соединены: `1` / `0` |
| `comment` | что заметил словами (необязательно) |

Ставить только `1` или `0`. Пустая ячейка = «не размечал», такая строка в обучение не пойдёт.

**Общий балл не размечаем.** Нужны пять отдельных критериев — иначе модель учится
непонятно чему: в общем балле смешаны темп, глубина и положение рук.

## Правила разметки, без которых датасет бесполезен

1. **Каждую 10-ю попытку размечает второй эксперт.** Скрипт посчитает согласие
   (каппу). Если эксперты не сходятся между собой (каппа < 0,5), обучение
   бессмысленно: сначала надо договориться о критериях.
2. **Один студент — минимум 2–3 попытки**, иначе нечего проверять.
3. **Нужно минимум два разных студента.** На записях одного человека проверить
   модель нельзя.
4. **Размечаем по видео, а не по подсказкам сервера.** Эксперт смотрит и решает сам,
   что видит; числа сервера при разметке не открываем, иначе разметка повторяет
   ошибки сервера.

## Сколько нужно

| Попыток | Что можно |
|---|---|
| 20–30 | проверить цепочку, найти ошибки камеры и ракурса |
| 100–150 | увидеть, какие признаки работают; каппа ориентировочно 0,4–0,55 |
| **300–400** | рабочий минимум для внедрения, каппа 0,6–0,75 |
| 800–1000 | уверенно выше 0,75, можно учить нейросеть на последовательностях |

## Порядок работы

```bash
# 1. поставить зависимости (один раз)
pip install -r requirements-train.txt
python tools/download_pose_model.py

# 2. положить записи в train_data/videos/, заполнить labels.csv
cp train_data/labels.example.csv train_data/labels.csv

# 3. видео → числа
python tools/export_dataset.py

# 4. обучение и отчёт
python tools/train_model.py --save
```

Результат: `train_data/report.md` — таблица «пороги сейчас против модели» по каждому
критерию, и `backend/models/technique_model.pkl`, если каппа достигла 0,7.

## Где взять записи

1. Временная запись на сервере (`RECORD_UPLOAD=1`, см. `УДАЛИТЬ_ПЕРЕД_ФИНАЛОМ.md`) —
   складывает файлы в `media/recordings/`. После занятия скачать и разложить по `videos/`.
2. Готовые видео с занятий — если они уже есть, конвертировать в 480p WebM:
   `ffmpeg -i in.mp4 -vf scale=-2:480 -c:v libvpx -b:v 800k out.webm`
3. Запись с телефона вручную — хуже: ракурс будет плавать, признаки поплывут.

Перед выгрузкой: видео с людьми — персональные данные. Нужно согласие, минимум
лишних копий, удаление после разметки и обучения.
