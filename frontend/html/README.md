# Испытания — платформа проведения и проверки испытаний

Платформа проведения и проверки испытаний: база, роли, режимы, интерфейс, прохождение —
плюс **видеоанализ техники по камере** (MediaPipe Pose на сервере, очередь на одну станцию).
Голосовая проверка (речь → текст) вынесена в отдельный этап и пока не включена.

**Стек:** Python 3.12+ · FastAPI · SQLAlchemy 2 · Jinja2 · SQLite локально / PostgreSQL в Timeweb Cloud.

---

## Что уже работает

| Блок | Реализация |

| Результаты | попытки: авто-балл по алгоритму, ручная оценка преподавателем, статус нейропроверки |
| Испытание | название, описание, режим (обучение/тестирование), субъект (человек/имитация предметами), время, критерии, камера/микрофон |
| Вопросы | одиночный выбор, множественный выбор (частичный балл), текстовый с эталоном, текстовый с ручной проверкой; баллы, подсказки |
| Режим обучения | сразу после ответа — верно/неверно, правильный ответ, подсказка |
| Режим тестирования | вердикт по ходу не раскрывается, только по завершении |
| Запросы от сайта | весь фронт работает через JSON API (`/api/...`), можно дергать извне |
| Ручной ввод | текстовые ответы + форма ручной оценки в результатах |
| Камера/микрофон | предпросмотр видео, индикатор уровня микрофона, учёт факта включения и длительности — **файлы не сохраняются** |
| **Видеоанализ техники** | кадры 15/с уходят на сервер → MediaPipe Pose → темп, глубина, прямые руки, вертикальность, кисти вместе, ракурс; очередь на одну станцию; балл и вердикт в результатах |
| Нейропроверка (голос) | заглушка: попытка получает `neural_status = pending`, пока не подключён ASR |

## Видеоанализ техники (камера → числа)

Камера на станции оценивает технику СЛР **без участия человека**: кадры уходят на сервер,
модель MediaPipe Pose находит скелет, наша геометрия считает показатели, по ним выставляется
балл и вердикт. Видео и кадры **никуда не сохраняются** — в базу попадают только числа.

```
браузер: камера → canvas 480×360 → JPEG (15 кадров/с)
   │  POST /api/attempts/{id}/frames   (один кадр = один запрос, ~9 мс)
   ▼
FastAPI: проверка прав → сессия активна? (очередь) → очередь кадров (30 шт)
   ▼
отдельный процесс: MediaPipe PoseLandmarker  → 33 точки + world-координаты в метрах
   ▼
геометрия (numpy/чистая математика): углы, темп, глубина, ритмичность
   ▼
БД: только агрегаты (темп, глубина, проценты по критериям) + балл и вердикт
```

### Что считается

| Проверка | Как считается | Порог |
|---|---|---|
| Руки прямые | угол плечо–локоть–кисть | ≥ 160° |
| Руки вертикальны | отклонение линии плечи→кисти от вертикали | ≤ 28° |
| Кисти соединены | расстояние между запястьями (world, метры) | ≤ 12 см |
| Кисти над грудиной | боковое смещение кистей от линии плеч | ≤ 16 см |
| Камера сбоку | разнос плеч / длина корпуса в кадре | < 0,45 |
| **Темп** | пики вертикального сигнала кистей → медиана интервалов | 100–120 /мин |
| **Глубина** | размах «пик → впадина» сигнала кистей | 5–6 см (допуск 4–7) |
| Ритмичность | коэффициент вариации интервалов | 0 — идеально ровно |

Балл 0–100: темп 25 · глубина 25 · прямые руки 20 · вертикальность 15 · кисти вместе 15.
Вердикт `pass` — от 70 баллов. Логика в `backend/app/vision/scoring.py`, пороги меняются там же.

### Замер на сервере 2 vCPU / 2 ГБ (факт, не оценка)

| Показатель | Значение |
|---|---|
| Время на кадр 480×360 | **18 мс** (55 кадров/с на одном потоке) |
| Память процесса с моделью | **307 МБ** |
| Размер модели `pose_landmarker_lite.task` | 5,6 МБ |
| Поток 15 кадров/с, 4 секунды | 60 кадров отправлено → **60 обработано, 0 потеряно** |
| Задержка ответа API на кадр | 9 мс (среднее) |
| Трафик со студента | ~1,9 Мбит/с (16 КБ на кадр) |

### Очередь: одна станция за раз

Согласованное ограничение: **одновременно обрабатывается одна попытка**, остальные ждут —
на сервере 2 ГБ это гарантирует стабильность. Очередь FIFO, кто раньше встал, тот раньше прошёл.

```
POST /vision/join   → {"status": "active"}                     слот свободен, начинаем
                    → {"status": "waiting", "position": 2,      стоим в очереди,
                       "eta_sec": 240, "queue_length": 1}       фронт показывает «вы 2-й»
```

Правила, без которых очередь ломается:

* **watchdog 20 секунд** — нет кадров → слот освобождается, очередь двигается
  (`HEARTBEAT_TIMEOUT`);
* **очередь кадров 30 штук** — при переполнении выбрасывается самый старый кадр,
  задержка не растёт (`FRAME_BUFFER`);
* **лимит очереди 20 человек** — дальше честный отказ «попробуйте позже» (`QUEUE_LIMIT`).

Если станция занята, прохождение **не блокируется**: студент отвечает на вопросы, а плашка
показывает «вы N-й в очереди». Кто-то выключил камеру или закрыл браузер — слот освободится сам.

### Эндпоинты

```
POST /api/attempts/{id}/vision/join      встать в очередь / получить слот
GET  /api/attempts/{id}/vision/status    позиция в очереди + живые показатели
POST /api/attempts/{id}/frames           один кадр → метрики (15 раз в секунду)
POST /api/attempts/{id}/vision/leave     закончить, итог сохраняется в попытку
GET  /api/vision/stats                   диагностика: слоты, жив ли воркер, потери кадров
```

Кадр принимается как `{"image": "data:image/jpeg;base64,...", "ts_ms": 1712345678}`,
не больше 2 МБ, только JPEG. Ответ: `{"accepted": true, "result": {"tempo_bpm": 112, ...}}`.

### Как включить

```bash
pip install -r requirements-vision.txt      # mediapipe, opencv-headless, numpy
python tools/download_pose_model.py         # модель 5,6 МБ → backend/models/
```

В `.env`: `VISION_ENABLED=1`. Всё остальное — по умолчанию под 2 ГБ сервер.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VISION_ENABLED` | `0` | выключено: кадры не принимаются, mediapipe не нужен |
| `MAX_VIDEO_SESSIONS` | `1` | сколько станций обрабатывается одновременно |
| `VIDEO_FPS` | `15` | целевая частота кадров с клиента |
| `FRAME_BUFFER` | `30` | очередь кадров у воркера |
| `HEARTBEAT_TIMEOUT` | `20` | секунд без кадров → слот освобождается |
| `QUEUE_LIMIT` | `20` | максимум ожидающих |
| `SESSION_ETA_SEC` | `240` | для оценки «ждать ~N мин» |
| `POSE_MODEL_PATH` | `backend/models/pose_landmarker_lite.task` | путь к модели |

Важно: `VISION_ENABLED=0` — сервер работает как раньше, `mediapipe` не требуется,
эндпоинты отвечают 503, а интерфейс просто не показывает плашку анализа.

Тесты (модель и mediapipe не нужны — проверяется геометрия, темп, очередь, оценка):

```bash
pip install -r requirements.txt pytest httpx
python -m pytest backend/tests -q      # 25 тестов
```

### Границы честно

* глубина по камере — **оценка ±1–2 см**; для аттестации по глубине нужен датчик в манекене
  (Laerdal QCPR) — это следующий уровень, камера остаётся для техники;
* порог 15 кадров/с нужен именно для темпа: на 2 кадрах/с сигнал 110/мин «складывается»
  и темп получается мусорным;
* на 2 ГБ одна станция; вторая — ждёт (см. очередь). Апгрейд до 4 ГБ даёт 2 станции,
  до 8 ГБ — 4 станции на 15 кадрах/с;
* кадры не сохраняются, поэтому разобрать спopную попытку «по видео» нельзя — только по числам.
