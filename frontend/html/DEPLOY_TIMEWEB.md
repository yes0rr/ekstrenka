# Деплой на Timeweb Cloud — с нуля, по шагам

Инструкция для варианта **App Platform (PaaS)**: код лежит в Git, Timeweb сам собирает и запускает,
даёт HTTPS-домен. Ниже — от пустого аккаунта до работающего сайта с базой PostgreSQL.

Ориентиры: ~40–60 минут на первый раз, из них 10 — ожидание сборки.
Понажимать в панели придётся в трёх местах: **Базы данных**, **App Platform**, **Firewall/домен** (по желанию).

Что понадобится:

- аккаунт Timeweb Cloud ([timeweb.cloud](https://timeweb.cloud)) с привязанной картой;
- аккаунт GitHub (можно GitLab/Bitbucket) — там будет лежать код;
- Git на компьютере;
- локально работающий Python 3.11+ (чтобы один раз проверить проект перед заливкой).

> Важно понимать заранее: в App Platform приложение и база — **два отдельных сервиса**.
> Приложение живёт в одной приватной сети с базой (это выбирается при создании и **не меняется потом**),
> база по умолчанию наружу не смотрит. Ниже это учтено в порядке шагов.

## Шаг 0. Что мы задеплоим

| Компонент | Что это | Где |
|---|---|---|
| Приложение | FastAPI + Jinja2, точка входа `main.py` → `app` | App Platform, Backend → FastAPI |
| База | PostgreSQL 16/17 | DBaaS («Базы данных») |
| Файлы | в БД и в контейнере; загружаемых файлов пока нет (медиа — заглушка) | — |
| Домен | бесплатный технический `*.twc1.net`, при желании — свой | App Platform |

Отдельных миграций нет: таблицы создаются автоматически при старте приложения
(`init_db()` в `backend/app/main.py`). Это нормально, пока схема не меняется; когда начнёт — добавим Alembic.

## Шаг 1. Проверить проект локально (5 минут)

Не пропускайте: если приложение не стартует у вас, оно не стартует и в облаке, а лог деплоя
читается тяжелее, чем консоль.

```bash
cd ispytaniya
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # локальный .env, в git не попадёт
python -m backend.app.seed         # демо-данные (один раз)
python run.py
```

Откройте `http://localhost:8000` → должен открыться экран входа.
Проверьте вход `teacher@example.com / teacher123`, создание испытания, прохождение под `student@example.com / student123`.
Остановить — `Ctrl+C`.

Тесты (необязательно, но быстро):

```bash
pip install pytest httpx
python -m pytest tests -q          # ожидаем: 2 passed
```

Если здесь всё хорошо — идём дальше.

## Шаг 2. Git-репозиторий

### 2.1. Проверить, что секреты не уедут в git

В проекте уже есть `.gitignore` с `.env`, `data/*.db`, `__pycache__/`. Убедитесь, что `.env` не в индексе:

```bash
git status --porcelain | grep -E "\.env$" && echo "СТОП: .env в индексе" || echo "ок"
```

### 2.2. Инициализировать репозиторий и сделать коммит

```bash
cd ispytaniya
git init
git add .
git commit -m "Испытания: каркас платформы (FastAPI + PostgreSQL)"
git branch -M main
```

### 2.3. Создать репозиторий на GitHub

Через сайт: **github.com → New repository** → имя `ispytaniya` → **Private** → без README/gitignore → **Create**.
Или через CLI, если установлен `gh`:

```bash
gh repo create ispytaniya --private --source=. --push
```

### 2.4. Залить код

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/ispytaniya.git
git push -u origin main
```

Пароль от GitHub для `push` не подходит — нужен **Personal Access Token**
(GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → доступ к репозиторию, право Contents: Read and write).
В поле пароля вставьте токен.

Проверка: файлы видны на GitHub, **файла `.env` там нет**, `requirements.txt`, `Dockerfile`, `run.py`, `main.py` — есть.

## Шаг 3. База данных PostgreSQL

1. В панели Timeweb Cloud слева: **Базы данных** → **Создать**.
2. **Тип базы данных**: PostgreSQL. Версия — 16 или 17 (обе поддерживаются приложением).
3. **Регион** — тот же, где будет приложение (например, Москва). Иначе приватная сеть между ними не сработает.
4. **Конфигурация**: минимальный пресет. Для учебного проекта этого хватит; увеличить можно позже.
5. **Приватная сеть**: выберите существующую или **создайте новую** (например, `ispytaniya-net`).
   Запомните её название — на шаге 4 нужно выбрать **ту же самую**.
   Публичный IP **не включайте**: приложению он не нужен, а базу в интернет лучше не выставлять.
6. **Имя базы, пользователь, пароль** — задайте свои и сохраните в надёжном месте.
   Пароль понадобится один раз в переменных окружения.
7. **TLS**: для новых баз включён по умолчанию — ничего делать не нужно (в приложении поставим `DB_SSLMODE=require`).
8. Нажмите **Создать** и дождитесь статуса «Работает» (2–5 минут).

### 3.1. Записать реквизиты подключения

Откройте созданную базу → вкладка **«Подключение»** (и **«Дашборд»**). Там есть готовые строки подключения.
Выпишите пять значений:

| Что | Пример | Куда пойдёт |
|---|---|---|
| Хост | `c-abc123.postgres.twc1.net` (или приватный IP) | `DB_HOST` |
| Порт | `5432` | `DB_PORT` |
| Имя БД | `ispytaniya` | `DB_NAME` |
| Пользователь | `ispytaniya_user` | `DB_USER` |
| Пароль | `********` | `DB_PASSWORD` |

Если в панели показан только приватный адрес — так и надо: приложение будет в той же приватной сети.
Публичный адрес понадобится только для подключения с вашего ноутбука (`psql`, DBeaver) — см. шаг 9.

## Шаг 4. Приложение в App Platform

1. Слева: **App Platform** → **Создать**.
2. Тип: **Backend** → **FastAPI**.
3. **Репозиторий**: подключите GitHub (авторизация + доступ к репозиторию) и выберите `ispytaniya`.
   Нет GitHub в списке — «Подключите git-репозиторий по URL» и приватный репозиторий с токеном.
4. **Ветка**: `main`. Опцию «Сборка по последнему коммиту» (автодеплой) оставьте включённой.
5. **Регион** и **конфигурация**: тот же регион, минимальный тариф.
6. **Приватная сеть**: выберите сеть, созданную на шаге 3 (`ispytaniya-net`).
   ⚠️ После деплоя это изменить нельзя — при ошибке придётся пересоздавать приложение.
7. Разверните **«Показать расширенные настройки»** и заполните:

**Зависимости** (системные пакеты, через пробел) — можно оставить пустым:
```
libpq-dev
```
(драйвер `psycopg[binary]` ставится из `requirements.txt` без компиляции, libpq нужен «на всякий случай»)

**Команда сборки** — замените предложенную целиком на:
```bash
apt install -y --no-install-recommends curl build-essential libpq-dev
pip install --upgrade pip
pip3 install --upgrade -r requirements.txt
```

**Команда запуска**:
```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```
(`main.py` в корне проекта — тонкая обёртка, которая отдаёт `app` из `app.main`; именно этого ждёт шаблон FastAPI в Timeweb.)

**Путь до директории проекта**: оставьте пустым (проект в корне репозитория: `backend/` и `frontend/` лежат рядом).

**Путь проверки состояния**: `/healthz`
Это важно: иначе платформа считает успехом просто «контейнер запустился». С `/healthz` неудачный запуск
не вытеснит рабочую версию, а после деплоя приложение будет перезапускаться само, если начнёт падать.

**Переменные** — нажмите «Добавить» и внесите (или загрузите файл `.env`, см. ниже):

| Переменная | Значение | Зачем |
|---|---|---|
| `APP_NAME` | `Испытания` | заголовок |
| `SECRET_KEY` | 64 случайных символа | подпись сессионных cookie. Сгенерируйте: `python -c "import secrets;print(secrets.token_hex(32))"` |
| `DB_HOST` | хост базы | подключение |
| `DB_PORT` | `5432` | подключение |
| `DB_NAME` | имя БД | подключение |
| `DB_USER` | пользователь БД | подключение |
| `DB_PASSWORD` | пароль БД | подключение |
| `DB_SSLMODE` | `require` | TLS до базы |
| `NEURAL_ENABLED` | `0` | нейропроверка пока заглушка |
| `SEED_DEMO` | `1` — только на первый запуск | создаст демо-пользователей и демо-испытание |
| `ALLOW_TEACHER_SIGNUP` | `0` | запрещает любому желающему регистрироваться преподавателем |
| `COOKIE_SECURE` | `1` | cookie только по HTTPS |

> Вместо пяти `DB_*` можно задать одну строку `DATABASE_URL`:
> `postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:5432/ИМЯ_БД?sslmode=require`
> Приложение само приведёт её к нужному драйверу. Отдельные `DB_*` удобнее: не надо кодировать
> спецсимволы в пароле.
>
> Загрузка списком: подготовьте файл **с именем ровно `.env`** (шаблон — `env.production.example`,
> переименуйте и впишите значения) и в блоке «Переменные» нажмите «Загрузить из файла».

8. **Информация о приложении**: имя (`ispytaniya`), проект — по желанию.
9. **Запустить деплой**. Первый раз занимает 5–10 минут: поднимается сервер, ставятся зависимости.

Смотрите вкладку **«Деплой»**: там построчный лог. Успех = статус приложения «Работает» и запись об успешном
завершении. Ошибки — в разделе «Если что-то пошло не так» ниже.

### 4.1. Где взять адрес сайта

Вкладка **«Дашборд»** приложения: публичный IP и технический домен вида
`https://ispytaniya-xxxx.twc1.net`. Приложение доступно по HTTPS (443), порт 80 тоже открыт.

Откройте `https://ВАШ-ДОМЕН/healthz` — должно вернуться `{"status":"ok","app":"Испытания"}`.
Затем `https://ВАШ-ДОМЕН/login`.

## Шаг 5. Первый вход и «закрыть дверь» (обязательно)

С `SEED_DEMO=1` в базе появились две учётки с общеизвестными паролями:

| Роль | Почта | Пароль |
|---|---|---|
| Преподаватель | `teacher@example.com` | `teacher123` |
| Учащийся | `student@example.com` | `student123` |

Порядок действий сразу после первого деплоя:

1. Войдите как `teacher@example.com` → кликните на своё имя в правом верхнем углу → **Аккаунт** →
   **Смена пароля** (минимум 8 символов). Сохраните новый пароль.
2. Создайте **себе** нормальную учётку преподавателя: выйдите → «Зарегистрироваться».
   Если `ALLOW_TEACHER_SIGNUP=0` уже стоит — временно поставьте `1`, передеплойте, зарегистрируйтесь,
   затем верните `0`.
3. Демо-учётки заблокируйте: **Пользователи** → «Заблокировать» напротив `student@example.com` и `teacher@example.com`.
4. В App Platform: **Приложение → Настройки → Редактировать** → `SEED_DEMO=0` → **Сохранить**
   (запустится новый деплой). Демо-данные при старте больше создаваться не будут.
5. `ALLOW_TEACHER_SIGNUP=0` — чтобы учащиеся не могли выдать себя за преподавателя.

Проверьте, что после передеплоя вход работает и данные на месте: это и есть проверка, что база
подключена правильно и переживает обновление приложения.

## Шаг 6. Приёмка: чек-лист после деплоя

Открывайте по порядку (подставляя свой домен):

- [ ] `https://ДОМЕН/healthz` → `{"status":"ok"}`
- [ ] `https://ДОМЕН/login` → страница входа, стили на месте (тёмная тема)
- [ ] `https://ДОМЕН/docs` → интерактивная документация API открывается
- [ ] Вход преподавателем → главная показывает сводку, «Испытания» пустые/с демо
- [ ] Создать испытание: название, режим «тестирование», критерии → добавить 2–3 вопроса → **Опубликовать**
- [ ] Выйти, войти учащимся → на главной видно опубликованное испытание
- [ ] Пройти: ответить на вопросы, **включить камеру и микрофон** (браузер спросит разрешение —
      это работает только по HTTPS, у Timeweb он есть по умолчанию)
- [ ] Завершить → страница результата с разбором, балл посчитан
- [ ] Войти преподавателем → «Результаты» → выставить ручной балл и комментарий → сохраняется
- [ ] «Логи» → видны input/output: вход, ответы, завершение, ручная оценка, с вашим реальным IP
- [ ] «Пользователи» → роли и блокировка работают
- [ ] Перезагрузить страницу под учащимся — сессия держится

Если всё зелёное — платформа живая и готова к показу.

## Шаг 7. Свой домен (по желанию)

1. App Platform → ваше приложение → вкладка **«Настройки»** (или «Дашборд») → **Домены** → **Добавить**.
2. Введите домен, например `exam.mycollege.ru`.
3. В DNS вашего регистратора создайте запись:
   - `A` → публичный IP приложения (из «Дашборда»),
   - либо `CNAME` → технический домен `*.twc1.net`.
4. Дождитесь проверки (от минут до нескольких часов, зависит от DNS).
5. HTTPS-сертификат платформа выпускает сама (Let's Encrypt). После привязки домена
   `COOKIE_SECURE=1` остаётся правильным значением.

## Шаг 8. Обновления и откат

**Обновить код:**

```bash
# локально
git add .
git commit -m "правка"
git push
```

App Platform с включённым автодеплоем пересоберёт и перезапустит приложение сам.
Если автодеплой отключён — на вкладке «Деплой» нажмите «Запустить деплой» и выберите нужный коммит.

healthcheck, конфигурацию) — можно.

## Шаг 9. Резервные копии базы

1. **Автоматические бэкапы** DBaaS: включены у managed-кластеров, смотрятся на вкладке «Резервные копии».
   Проверьте расписание и срок хранения — и один раз **попробуйте восстановить** в тестовый кластер.
2. **Ручной дамп** (страховка перед крупными изменениями):

```bash
# с ноутбука: временно включите базе публичный IP и добавьте свой IP в разрешённые
PGPASSWORD='ПАРОЛЬ' pg_dump -h ХОСТ -p 5432 -U ПОЛЬЗОВАТЕЛЬ -d ИМЯ_БД \
  --no-owner --no-privileges -Fc -f backup_$(date +%F).dump
```

Восстановление:

```bash
PGPASSWORD='ПАРОЛЬ' pg_restore -h ХОСТ -p 5432 -U ПОЛЬЗОВАТЕЛЬ -d ИМЯ_БД \
  --clean --no-owner backup_2026-10-22.dump
```

3. После дампа **выключите публичный IP** базы (вкладка «Сеть»).

## Шаг 10. Безопасность: короткий чек-лист

- [ ] `SECRET_KEY` — случайные 64 символа, нигде не опубликован (в git его нет)
- [ ] `.env` не в репозитории; переменные заданы в панели App Platform
- [ ] `SEED_DEMO=0`, демо-учётки заблокированы, пароли сменены
- [ ] `ALLOW_TEACHER_SIGNUP=0` — преподавателей создаёт только администратор (через раздел «Пользователи»)
- [ ] `COOKIE_SECURE=1`, домен только по HTTPS
- [ ] у базы **нет** публичного IP (кроме моментов, когда делаете дамп)
- [ ] доступ к панели Timeweb — с 2FA
- [ ] «Логи» периодически просматриваются: `login_failed` пачками = кто-то подбирает пароль

## Если что-то пошло не так

Сначала всегда — вкладка **«Деплой»** (лог сборки) и вкладка **«Логи»** (лог приложения).

| Симптом | Причина | Что делать |
|---|---|---|
| Деплой падает: `ModuleNotFoundError: No module named 'app'` | команда запуска не видит пакет | команда запуска `uvicorn main:app --host 0.0.0.0 --port 8000`, «Путь до директории проекта» пустой |
| `ModuleNotFoundError: fastapi/sqlalchemy` | не установились зависимости | в команде сборки должна быть строка `pip3 install --upgrade -r requirements.txt` |
| Деплой «не прошёл проверку состояния» | `/healthz` не отвечает; приложение слушает не тот порт | проверьте `--port 8000` и `0.0.0.0`; локально `curl localhost:8000/healthz` |
| Открывается 502 / пустая страница | приложение слушает `127.0.0.1` | слушать `0.0.0.0` (в `run.py` это уже так; при ручной команде — флаг `--host 0.0.0.0`) |
| `psycopg.OperationalError: connection refused` / timeout | приложение не в той приватной сети, что база | пересоздать приложение, выбрав **ту же** приватную сеть |
| `password authentication failed` | неверные `DB_USER` / `DB_PASSWORD` / `DB_NAME` | перепроверить на вкладке «Подключение», пароль без лишних кавычек |
| `server does not support SSL` / ошибка TLS | `DB_SSLMODE` не подходит | `require` (или `prefer`); для старых баз TLS включается в панели базы |
| `role "..." does not exist` | пользователь БД указан с префиксом/опечаткой | скопируйте имя из панели целиком |
| Всё работает, но после передеплоя данные пропали | использовался SQLite внутри контейнера | только `DB_*`/`DATABASE_URL` на PostgreSQL; диск контейнера не постоянный |
| `Invalid or expired session`, разлогинивает | меняли `SECRET_KEY` | это ожидаемо, войдите заново |
| Камера/микрофон не включаются | нет HTTPS или запрет в браузере | открывайте `https://`, разрешите доступ в настройках сайта |
| Стили не грузятся | статика монтируется из `frontend/css` и `frontend/js` | проверить, что папка `frontend/` есть в репозитории и файлы закоммичены |

Полезное: чтобы проверить приложение «как снаружи», можно временно поставить `SEED_DEMO=1` и зайти
демо-учёткой — но не забудьте потом `0` и блокировку.

## Альтернативы

**Docker вместо шаблона FastAPI.** В проекте есть `Dockerfile`. При создании приложения выберите
тип «Docker» → репозиторий. Команда запуска не нужна: `CMD ["python", "run.py"]` читает `PORT`
и `HOST` из окружения. `EXPOSE 8000` в файле уже есть. Плюс: полностью воспроизводимое окружение.
Минус: сборка чуть дольше.

**Обычный VPS (когда понадобится).** Переезжайте, если нужны: постоянный диск под записи видео,

## Стоимость и масштаб

Точные цены смотрите в панели — они меняются. Ориентир: минимальные тарифы приложения и managed
PostgreSQL считаются отдельно (managed PostgreSQL у Timeweb Cloud стартует от нескольких сотен рублей
в месяц), плюс бесплатный технический домен. Для одного колледжа и десятков студентов минимальной
конфигурации достаточно; узкое место при массовом тестировании — не CPU, а одновременные видеопотоки
(они пойдут через браузер) и запись медиа, когда её включим.

Первые шаги после запуска: посмотрите «Логи» через день — там видно реальную нагрузку и ошибки.
